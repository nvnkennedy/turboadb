Command line

Everything TurboADB does, as one-line commands you can script. Every device command takes -s SERIAL (or -s @saved-name); add --adb-host HOST to drive a device plugged into another PC.

Getting started

adb and scrcpy download themselves on first use. turboadb -h lists the commands and turboadb <command> -h shows one command's options.

pip install turboadb
turboadb doctor                                   # are adb and scrcpy available?
turboadb devices                                  # what's attached
turboadb -s 10BE330KG9000AF info                  # one device by serial
turboadb -s 192.168.1.50:5555 screenshot shot.png # a network device
turboadb --adb-host lab-pc-01 -s DEVICE info      # a device on another PC
turboadb targets add bench network 192.168.1.50   # save a target once…
turboadb -s @bench info                           # …and use it by name

Global options, output and exit codes

Device options work before or after the command name, so turboadb -s SERIAL info and turboadb info -s SERIAL are the same. The setup commands (doctor, fetch-tools, upgrade-tools, self-update, shortcut, gui, deploy-serve) drive no device, so of these they take only --json.

OptionMeaning
-s, --serial SERIALThe device: a USB serial or host:port, or @NAME for a saved target. Omit it when only one device is attached.
--adb-host HOSTUse another PC's adb server (that PC runs turboadb serve).
--adb-port PORTadb server port (default 5037).
--adb-path PATHUse this adb executable.
--scrcpy-path PATHUse this scrcpy executable.
--timeout SECONDSTimeout for each command, and for push, pull and bugreport too (defaults: 60 s, transfers 600 s).
--jsonOne JSON document on stdout (progress and warnings go to stderr): data as JSON, actions as {"ok": …, "message": …}, returned values as {"ok": …, "result": …}, saved files as {"ok": …, "path": …}, a --full report as {"ok": …, "report": …}. The setup commands take it too; logcat streams plain lines.
-V, --versionPrint the TurboADB version.
Exit codeMeaning
0Success.
1The action failed or the device refused it (one ERROR: line explains why).
2Wrong command-line usage.
3adb not found — run turboadb fetch-tools.
130Stopped with Ctrl+C.

shell and adb exit with the device command's own code.

EnvironmentEffect
TURBOADB_ADBPath to the adb executable.
TURBOADB_SCRCPYPath to the scrcpy executable.
TURBOADB_AUTO_FETCH=0Never download adb / scrcpy automatically.
VISUAL, EDITORThe editor turboadb edit opens.

Files

Paths are checked first: a missing path, or a folder without -r, is an error and nothing changes.

CommandWhat it doesArguments & options
pushUpload a file or folder to the device, with progress.LOCAL REMOTE --json
pullDownload a file or folder from the device, with progress.REMOTE LOCAL --json
lsList a device folder: permissions, owner, size, date, name.[PATH=/sdcard] --json
mkdirCreate folders, with any missing parents.PATH…
touchCreate empty files.PATH…
rmDelete files, and folders with -r (/ is always refused).PATH… -r
mvMove or rename; into a folder when the destination is one.SRC DST -f
cpCopy a file or folder (never a folder into itself).SRC DST
statPath, real path, type, size and octal mode.PATH --json
editEdit a device text file in a local editor; saved back only when changed, keeping its permissions.PATH --editor "code --wait"
 
turboadb -s SERIAL push app.apk /data/local/tmp/
turboadb -s SERIAL ls /sdcard/Download
turboadb -s SERIAL mv /sdcard/clip.mp4 /sdcard/Movies
turboadb -s SERIAL rm -r /sdcard/logs
turboadb -s SERIAL edit /data/local/tmp/config.ini

Sharing devices with other PCs

serve never downloads adb by itself: its startup task runs as SYSTEM, where that would put a second adb in another profile and bind port 5037 with it. Run turboadb fetch-tools there first if adb is missing.

CommandWhat it doesArguments & options
serveShare this PC's adb server so others can use --adb-host (opens the firewall; needs Administrator), check it, or stop sharing.--port 5037 --startup-task --install-startup --uninstall-startup --status --stop --json
deploy-serveSet up serve on remote Windows PCs over WinRM (needs turboadb[winrm]).HOST… -u USER -p PASSWORD --port 5037 --ssl --winrm-port --no-update --test --json
 
# on the PC with the device:
turboadb serve --startup-task
turboadb serve --status

# or from your machine:
turboadb deploy-serve lab-pc-01 lab-pc-02 -u "DOMAIN\user" --ssl

More
